# Proposal

## Why

第一階段已能找出缺口，但缺口仍是一條直線：苫小牧到札幌被斜切過去，青函隧道與新幹線隧道也只是虛線。使用者搭火車時訊號中斷是最常見的情況，現有 App（包括 Relive）都只會拉直線；沿實際鐵路補齊，是 TripWeave 超越它們的核心功能。

## What Changes

- 匯入軌跡後**自動**判斷每個缺口是否為搭乘鐵路，若是就沿實際鐵路補齊；不需要任何按鈕或選擇
- 軌跡與缺口先立即顯示，補路在背景進行，完成一段就顯示一段
- 補齊的路段以「推算」樣式顯示，與實際記錄、未補齊的缺口三者明顯不同，並附上依據（路線名稱、沿鐵路距離）
- 缺口一端不在鐵路上（例如下車後 GPS 才恢復）時，只補鐵路的部分，其餘維持缺口樣式
- 判斷不出是鐵路的缺口維持原樣，不硬補
- 建立自有的鐵路資料：每月由 GitHub Actions 從 OpenStreetMap 產生、切成網格放在自己的網站，App 只下載缺口附近的網格；不向第三方服務送出位置
- 先以日本、台灣驗證整條流程，再擴充到全球

不在本次範圍：飛機、渡輪、道路、潛水等其他交通方式；手動修正推算結果。

## Capabilities

### New Capabilities
- `gap-filling`：判斷缺口的交通方式並產生推算路段（本次為鐵路），以及推算結果的呈現資訊與限制
- `rail-data`：鐵路網資料的涵蓋範圍、更新方式與取得方式

### Modified Capabilities
- `track-map-view`：「區分實際記錄與缺口」改為同時區分實際記錄、推算路段與缺口三種樣式

## Impact

- 新增資料產生流程（GitHub Actions 排程、OSM 資料下載與轉換腳本），以及部署到 GitHub Pages 的網格資料
- `src/core` 新增鐵路網圖、路徑搜尋與補路判斷；`src/map` 新增推算路段圖層
- Service worker 新增鐵路網格的快取
- 測試資料新增 `Day1+2.kml` 缺口附近的鐵路網格
