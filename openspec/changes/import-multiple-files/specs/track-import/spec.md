# Spec Delta

## MODIFIED Requirements

### Requirement: 無法匯入時提供明確訊息
系統 SHALL 在檔案格式不支援、內容損毀或沒有任何軌跡時，顯示說明原因的錯誤訊息。一次選取多個檔案時，其餘可以匯入的檔案 MUST 照常匯入，並列出無法匯入的檔名與原因；所有選取的檔案都無法匯入時，MUST NOT 改變目前已載入的軌跡。

#### Scenario: 匯入不支援的格式
- **WHEN** 使用者選擇一個 PDF 檔
- **THEN** 系統顯示「不支援的檔案格式」並列出支援的格式

#### Scenario: 檔案中沒有軌跡
- **WHEN** 使用者匯入一個只有地標點、沒有線段的 KML
- **THEN** 系統顯示「檔案中找不到軌跡」

#### Scenario: 多個檔案中有一個無法匯入
- **WHEN** 使用者一次選取兩個 GPX 與一個 PDF
- **THEN** 兩個 GPX 合併匯入，並顯示該 PDF 的檔名與「不支援的檔案格式」

#### Scenario: 選取的檔案全部無法匯入
- **WHEN** 已載入一趟旅程後，使用者一次選取兩個 PDF
- **THEN** 顯示兩個檔案的錯誤原因，原本的旅程保持不變

## ADDED Requirements

### Requirement: 一次匯入多個檔案
系統 SHALL 讓使用者在同一個「匯入軌跡」操作中選取一個或多個 KML、GPX 檔，合併成一趟旅程。再次匯入時 MUST 以新選取的檔案取代目前的旅程。

#### Scenario: 匯入同一趟旅行的兩天
- **WHEN** 使用者一次選取 2024/8/14（上野到札幌）與 2024/8/15（札幌到釧路）兩個 GPX
- **THEN** 地圖顯示上野經札幌到釧路的完整旅程

#### Scenario: KML 與 GPX 混用
- **WHEN** 使用者一次選取一個 KML 與一個 GPX
- **THEN** 兩個檔案都被匯入並合併

### Requirement: 依時間排列檔案
合併時 SHALL 依各檔案第一個有時間的點排列；任一檔案沒有時間資料時，改依檔名的自然順序排列（數字依數值比較）。排列不得受選取順序影響。

#### Scenario: 選取順序與時間順序不同
- **WHEN** 使用者先選 8/15 的檔案、再選 8/14 的檔案
- **THEN** 旅程仍以 8/14 在前、8/15 在後的順序合併

#### Scenario: 沒有時間資料時依檔名
- **WHEN** 匯入沒有時間資料的「Day10.kml」與「Day2.kml」
- **THEN** 以 Day2 在前、Day10 在後的順序合併

### Requirement: 讀取進度
同時匯入多個檔案時，系統 SHALL 顯示讀取進度（已完成數／總數），讀取期間畫面 MUST 維持可操作。

#### Scenario: 讀取 14 個檔案
- **WHEN** 使用者一次選取 14 個 GPX
- **THEN** 畫面依序顯示「讀取中 1/14」到「讀取中 14/14」，完成後顯示旅程

### Requirement: 旅程摘要
匯入多個檔案時，系統 SHALL 在畫面上顯示檔案數；軌跡有時間資料時另外顯示日期範圍。

#### Scenario: 兩天的旅程
- **WHEN** 匯入 2024/8/14 與 8/15 兩個 GPX
- **THEN** 畫面顯示「2 個檔案」與「2024/8/14–8/15」
